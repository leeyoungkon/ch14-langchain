# 주문 챗봇 음성 입출력 수정본

첨부하신 Python 코드를 바탕으로 웹 화면(HTML 및 JavaScript)만 교체했습니다. 주문 SQL 검증·DuckDB·MinIO·고객 MCP·LLM·환경변수는 기존 그대로입니다. voice.html은 화면 참고용이며, 실행에 필요한 화면은 app.py에 이미 포함되어 있습니다.

## 적용

1. 기존 app.py를 백업하고 이 폴더의 app.py로 교체합니다. 기존 패키지와 환경변수 설정은 그대로 사용합니다. 음성 기능 때문에 추가할 Python 패키지는 없습니다.
2. 로컬 실행 명령은 아래와 같습니다. 기존 환경의 .env 또는 환경변수가 필요합니다.

   uvicorn app:app --host 0.0.0.0 --port 8000

3. Kubernetes에서 이미지에 app.py를 넣었다면 이미지를 다시 빌드하고 새 태그로 Deployment를 갱신해야 합니다. ConfigMap이나 볼륨으로 코드를 연결했다면 해당 배포 방식에 맞게 변경 후 재시작합니다.
4. 브라우저는 http://localhost:8000 또는 HTTPS 주소로 접속합니다. 원격 IP의 HTTP NodePort 주소로 접속하면 음성 입력 버튼은 비활성화됩니다.
5. 기존 서비스가 있다면 다음 명령으로 localhost에서 접속할 수 있습니다. 서비스명과 서비스 포트는 실제 값으로 바꾸세요.

   kubectl port-forward svc/<서비스명> 18000:<서비스포트>

   접속 주소: http://localhost:18000

   원격 Kubernetes API에 접속 가능한 kubeconfig가 PC에 설정되어 있어야 합니다.

## 사용 순서

- Chrome에서 음성 입력을 누르고 마이크 권한을 허용한 후 한국어로 질문합니다.
- 말을 마치면 인식이 종료됩니다. 계속 듣고 있으면 인식 마치기를 누릅니다.
- 인식된 질문을 확인·수정하고 질문 전송을 누릅니다. 인식 후 자동 전송을 켜면 확정된 인식 결과를 자동 전송합니다.
- 답변은 화면에 표시되며 답변 자동 읽기가 켜져 있으면 음성으로도 출력됩니다.
- 다시 듣기와 읽기 중지를 사용할 수 있습니다. 음성 목록에서 PC·브라우저가 제공하는 음성을 고를 수 있습니다.
- 새 음성 입력이나 질문 전송을 시작하면 재생 중인 답변 읽기를 중지합니다.
- Enter로 전송하고 Shift+Enter로 줄바꿈합니다.

## 처리 경로

마이크 → 브라우저 음성 인식 → 질문 텍스트 → 기존 /chat → 기존 Agent·DuckDB·MCP → 답변 텍스트 → 브라우저 음성 합성

## 실행 조건과 범위

- 음성 인식은 브라우저 Web Speech API를 사용합니다. 서버에 Whisper나 TTS 모델을 설치하는 방식이 아닙니다.
- 브라우저 음성 인식은 외부 인식 서버를 사용할 수 있으며 인터넷 연결이 필요할 수 있습니다. 외부 음성 전송 없는 구성이 필요하면 서버 STT/TTS 방식으로 별도 변경해야 합니다.
- 음성 인식 지원 여부, 마이크 권한, 한국어 음성 및 음질은 브라우저·운영체제 환경에 따라 달라집니다. 음성 기능 실패 시 텍스트 입력과 답변은 계속 사용할 수 있습니다.
- 브라우저에서 자동 읽기가 차단되면 다시 듣기를 직접 누르세요.
- 원본 코드의 CHAT_MODEL 기본값은 gemma3:12b입니다. 기존에 환경변수로 Qwen을 지정했다면 그대로 적용됩니다. 모델 설정과 도구 호출 지원 여부는 기존 환경에서 확인해야 합니다.
- 기존 코드에는 별도 사용자 인증이 없습니다. 기존 접근 통제 환경을 유지하세요.

## 확인한 항목

Python 문법, JavaScript 문법, 백엔드 코드 유지 여부 및 모의 브라우저 환경의 텍스트 전송·음성 인식 결과 반영·자동 전송·답변 읽기 동작을 확인했습니다. 실제 마이크, 스피커와 사용자 서버의 Ollama·MinIO·MCP 연결은 이 환경에서 실행하지 않았습니다.
